# Sync Strategy Rules (Offline-First)

산책 세션(WalkingSession) 및 주요 데이터 기록에 적용되는 오프라인 우선 동기화 규칙입니다.

## 1. Entity 구조
- 동기화 상태를 추적하기 위한 필드 필수 포함.
  - `isSynced: Boolean` (기본값 false)
  - `syncAttempts: Int` (시도 횟수 제한용)

## 2. Repository 패턴 (Offline-First)
1. **로컬 저장 우선**: 네트워크 상태와 관계없이 로컬 DB(Room)에 즉시 저장.
2. **백그라운드 동기화**: 저장 후 즉시 비차단(non-blocking) 방식으로 서버 전송 시도.
3. **네트워크 가용성 체크**: 네트워크가 없을 경우 동기화 시도를 건너뛰고 나중에 재시도.

## 3. 동기화 로직
- 실패 시 `syncAttempts`를 증가시키고 최대 3회까지 재시도.
- 수동 동기화 버튼을 UI에 제공하여 사용자가 원할 때 다시 시도할 수 있게 함.
- 동기화 실패 시 로컬 데이터를 삭제하지 마십시오.

## 4. UI 피드백
- 데이터의 동기화 여부를 아이콘 등으로 표시하여 사용자에게 알림.
- 동기화되지 않은 데이터의 개수를 표시하고 수동 동기화 트리거 제공.
