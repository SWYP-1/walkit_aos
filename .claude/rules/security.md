# Secure Development Principles

## 1. 입력 값 검증 및 살균
- 사용자 입력을 파일 접근, 명령어 실행, DB 쿼리에 직접 사용하지 마십시오.
- 모든 외부 입력(User, API, Third-party)은 사용 전 유효성 검사를 거쳐야 합니다.

## 2. 민감 정보 보호
- API 키, 인증 정보, 개인키 등을 코드나 공용 설정 파일에 하드코딩하지 마십시오.
- `BuildConfig` 또는 안전한 환경 변수 관리 시스템을 사용하십시오.
- 로그(Logs)에 토큰, 비밀번호, 개인 식별 정보를 기록하지 마십시오.

## 3. 안전한 통신
- 모든 외부 통신은 반드시 HTTPS/TLS 등 암호화된 프로토콜을 사용해야 합니다.
- `network_security_config.xml`을 통해 Cleartext 트래픽을 제한하십시오.

## 4. 보안 통제
- 권한 검사, 인증, 중요한 비즈니스 로직을 클라이언트 사이드 로직에만 의존하지 마십시오. (서버 사이드 검증 필수)
- 보안 체크나 예외 처리를 임의로 무시하거나 억제하지 마십시오.
